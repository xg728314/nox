NOX 기능정의서

유흥업소 (호빠) 운영 관리 웹앱의 화면 · 인터랙션 · 비즈니스 규칙 명세. 개발자가 각 요소를 클릭했을 때 어떤 메뉴가 뜨고 어떤 처리가 일어나는지 화면별로 정리.

00 · OVERVIEW

시스템 개요

NOX 는 유흥업소 14개 매장 (건물 5–8층) 을 하나의 시스템으로 묶는 운영 관리 앱이다. 종이 장부 · 카톡 도배를 대체한다.

주요 도메인

세션 (room_sessions)
방 하나가 손님을 받고 종료까지 = 1개 세션. 참여자 · 주문 · 정산의 뿌리.
참여자 (session_participants)
세션에 들어간 아가씨 1건 = 1 row. 같은 아가씨가 연장하면 새 row 추가 (라운드).
영업일 (business_date)
KST 06:00 기준 24시간. 자정 넘어 시작한 세션도 이전 영업일에 속함.
매장 (stores)
같은 건물 5–8층에 위치. 각 매장마다 owner · manager 다수 · hostess 다수.
이적 (transfer_requests)
아가씨가 다른 매장에서 일할 때. 원소속 (origin_store) 은 영원히 유지.
01 · ROLES

사용자 역할 (Role)

모든 페이지 · API 는 역할과 매장 소속으로 접근이 결정된다. counter 는 enum 이 아닌 위임 UI actor (owner/manager 가 사용).

역할본연의 화면주요 권한
owner/owner매장 정산 열람 · 스태프 관리 · 모든 매출. 실장/아가씨 개별 수익은 비노출 (열람 권한 규칙).
manager/manager, /m/*본 매장 세션 · 참여자 · 정산 · 배정. 타매장 아가씨는 초대만.
hostess/me본인 정산만 열람 (읽기 전용). 실장수익 비노출.
counter/counterenum X. owner/manager 로 로그인한 카운터 PC.
super_admin전 화면매장 scope 우회. 개발/운영.
Auth 원칙
  • 모든 API 는 resolveAuthContext(req) 로 Bearer + membership 검증
  • 인원 식별은 membership_id 로 (user_id 아님 — 같은 사람이 여러 매장 소속 가능)
  • 데이터 scope 은 store_uuid 로 (numeric store_id 사용 금지)
  • membership 은 status='approved' + is_primary=true 만 유효
